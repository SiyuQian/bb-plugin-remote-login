# Pinned Console self-identity adapter

The experimental `oci_web` flow connects a fresh owned host browser, protected phone controller, exact independent self-identity verification, retained-context handback and two restricted reads. Registration and automated fixtures do not establish actual iPhone or Oracle account acceptance. CLI evidence cannot substitute for Console identity.

## Anonymous public source evidence

On 2026-11-11, an anonymous `GET https://cloud.oracle.com/` returned HTTP 200 without redirects. Its HTML selected Console build `4.26.2hotfix.2`. Only that HTML, its public script assets and Oracle documentation were fetched. No page JavaScript, OAuth challenge, account API, existing browser/profile or account configuration was used for research. The bundles are not vendored.

The shell's module `52164` constructs `SelfServiceMeApi` with the active authenticator's `getFetchApi()` and identity-domain stripe URL. Module `30045.g` keeps that authenticator and bound fetch function. The generated client's module `94627`, exported through `80002`, fixes the self-read to `GET /admin/v1/Me`.

The authentication bundle connects `SoupAuthenticator.initializeFetchApi()` to `BMCClient.fetch`. Its request authorizer signs with the current browser context's authentication material, and `BrowserIOKernel.deliverHttp()` uses the page's fetch. The generated request therefore uses the Console's own signed request path; the adapter does not export or reconstruct its key/token. The pinned webpack runtime permits a fixed internal callback to obtain its module loader. These are reviewed build internals, not a stable Oracle extension API; any incompatible source delivery fails closed.

Oracle documents `Me` as self-profile access. Its response includes immutable user `ocid` and read-only `tenancyOcid`/`domainOcid`; the adapter requires all three and an active user, and compares them exactly with independently selected expectations. Display labels and token claims alone are insufficient. [Me reference](https://docs.oracle.com/en/cloud/paas/iam-domains-rest-api/op-admin-v1-me-get.html)

Identity Domains supports OAuth tokens and OCI request signatures. That does not prove cookie-only access or make a CLI signer/another OAuth application prove the active Console principal. This adapter uses the observed same-frame Console signer path instead. [Oracle authorization](https://docs.oracle.com/en-us/iaas/Content/Identity/api-getstarted/api-managing-authorization.htm)

## Adapter contract

`oci-console-protocol.ts` accepts a private preselected user OCID, tenancy OCID, domain OCID and exact HTTPS identity-domain origin, currently Sydney/oc1 only. The origin is never chosen from returned profile data. `oci-console-source.ts` must attach before Console navigation and observe all four pinned scripts delivered to the current main frame. Browser cache, service workers, redirects, foreign frames, wrong MIME/build and changed bytes cannot attest that document. Every new critical script delivery revokes previous proofs synchronously before its body is awaited. Capture/assert refuse pending or changed attestation revisions; a matching duplicate requires a fresh proof. Its issued proof is opaque and bound to that page document; JSON flags cannot replace it. The owner must disable browser cache and bypass service workers before login redirects so cached source deliveries cannot be accepted.

`oci-console-verifier.ts` accepts an existing private Puppeteer page and a trusted worker `assertOwned` callback. It captures the browser/context/target identity and fences the main-frame document generation. The callback must assert the genuine private lease, attempt/thread/project/environment/host/root binding, current control proof and deadline, accepted paired-control gate, exclusive control phase, safe browser/profile ownership and TLS policy. The owner must pause phone/agent input and install an actual request barrier during verification. `BMCClient.fetch` attempts token refresh before dispatching Me, so this adapter alone does not guarantee an exact single-request or no-reauth policy. The owned driver permits only the fixed marked Me GET and its correlated required preflight during verification, and denies refresh/reauth requests. An assertion callback alone is not that request barrier. The owner must also deny downloads, disable cache, bypass service workers and retain normal TLS verification. This module does not create that lease or establish physical phone identity.

The fixed private bridge accesses the pinned Auth singleton and generated self-read client. It rejects tenancy override and a changed authenticator, fetch binding or identity-generation hints. It requests only `id,ocid,tenancyOcid,domainOcid,active`, with a fresh request identifier, omitted cookies, no-store caching and redirects refused. Untrusted identity hints only fence context changes; the service response establishes the match.

Before dispatch, the bridge hashes the signed authorization header inside the page. The worker requires a correlated CDP wire-header event with that same digest, exact method/URL/request identifier, and the owned main-frame/loader identity. It requires one successful network JSON response, rejects redirect/cache/service-worker evidence (including memory-cache events received before correlation or after completion) and bounds captured response bytes. A redirect on the correlated request ID is refused even if it loses its marker header. A page evaluation returning success without that network exchange cannot verify anything. Raw headers, response identity, browser keys and Oracle authentication remain inside the worker.

After exact profile matching, the verifier rechecks ownership, source proof, current Console context and deadline, including after awaited CDP/handle cleanup. It returns only bounded match facts and the public source build. Cancellation owns a page-side AbortController: it aborts only the self-read, synchronously restores only its own fetch wrapper, invalidates the bridge and waits for settlement before disposing handles/CDP. Late handle/session acquisition is drained or cleaned when it arrives. Unconfirmed cancellation/acquisition cleanup poisons the adapter with `cleanup_uncertain`; the owned driver must hold or close that context before resuming any control. Navigation, new targets, logout traffic, expiry and changed authority defeat late evidence. Each verification is bounded; no public success setter, URL, script, selector, credential or header argument exists.

The source boundary and its digest operation are replaceable only as internal external-dependency seams for tests; tiny digest fixtures are not production source evidence. Production defaults require the fixed four hashes. Tests use a newly owned Chrome process and loopback TLS server with synthetic Console modules, signature strings and profile data. Their local certificate override is fixture-only; production ownership must enforce normal TLS verification. Tests cover actual wire correlation, authorization substitution, missing network evidence, wrong/missing identities, service rejection, cache/service-worker metadata and late ownership/context changes. They do not establish acceptance by Oracle.

## Exact future live acceptance gate

1. Provision the owner's control root separately and complete the protected synthetic control round. Independently select the exact user/tenancy/domain/origin; keep those values private.
2. Create a fresh owned Console browser/context on the explicit host. Attach the real source attestor before navigation. Do not import cookies or read any existing profile/configuration.
3. Let the phone perform Oracle login through the private frame/input channel. Do not give agent browser access during authentication.
4. Freeze input and run this fixed self-read in that same main frame. Require real Oracle HTTP acceptance, all expected OCIDs and the original context/authority after awaits. The authenticated runtime, CORS behavior and required response fields must be demonstrated for this pinned build and target domain.
5. Retain that exact browser and issue a short-lived opaque reference only after verification. The first restricted agent operation should repeat the fixed protected self-read in the same context, with fresh ownership/identity checks. Subsequent approved Console reads must use this signer/context, never the CLI account lease or arbitrary evaluation.
6. Confirm that wrong-account/domain, logout, root/proof expiry and context replacement refuse further reads, and that stop closes only owned resources. No current fixture or static source match supplies this live evidence.

Actual phone/Oracle acceptance, the full device/fault matrix and production delivery remain unfinished. Console support must not be represented as complete until this full gate is exercised; a separate SSO application or CLI login does not finish it.


## Registered private browser and original task

`remote_login_request({mode:"oci_web",wait:true})` uses the injected original project/thread and its current environment host. The runtime preflight requires macOS arm64 and an available browser; the actual opener independently requires Chrome `157.0.8103.50` and Puppeteer `25.16.0`. A separate owner root, live scope proof and recent verified-and-closed synthetic control receipt gate target selection and browser startup. The private phone form supplies the expected user, tenancy, domain and exact domain origin; none enter the coordinator, public form payload or native result. Console does not use OCI CLI source inventory as authorization and never borrows CLI credentials. The shared macOS process-ownership inspector currently invokes `/opt/homebrew/Cellar/oci-cli/3.88.0/libexec/bin/python`; that exact local interpreter installation is still a runtime prerequisite even for Console-only use. The method preflight now observes the current process ownership and refuses queuing when that inspection is unavailable; actual startup still rechecks its own process and profile. A standalone inspector discovery/package contract remains follow-up work.

The opener creates a new 0700 owned Chrome profile, pipes CDP privately, enforces normal TLS, denies downloads, disables cache and bypasses service workers. The closed provider URL set covers reviewed Oracle sign-in origins and identity domains; foreign federation, popups, browser/OS dialogs and arbitrary existing browsers are unsupported. Source observation begins before navigation. No public route accepts URLs, scripts or selectors.

Handback immediately freezes frame/input and reserves exclusive verification. It drains queued input and tracked HTTP under a global network block before allowing one marked same-main-frame Me GET and its correlated CORS preflight. Refresh, reauthentication and unrelated requests remain blocked. A retained browser stays blocked after verification; a subsequent read must freshly verify identity. `read_page` verifies before and after capturing only the visible current title and up to twenty headings in the same document generation. It excludes form ancestors and never returns inputs, HTML, URLs, cookies or screenshots. Bounded text projection redacts expected identifiers and authentication-like strings; page text is untrusted data.

The protected handback response returns only pending/verified. The original native wait independently checks the durable receipt, current root/host binding and a fresh retained-browser proof before claiming its result. Only that original result contains an opaque `browserRef`. `remote_login_console_read({attemptId,browserRef,request:{operation:"read_identity"|"read_page"}})` requires the same injected project/thread, verified receipt, claimed-uncertain original result and unexpired private lease. History/status never contain the reference. There is no navigate, click, form edit, arbitrary evaluation or cookie/token export operation.

A protected pending/verified handback acknowledgement transfers cleanup responsibility to the host even if the phone view unmounts. Explicit Stop still cancels; an aborted/unmounted view cannot submit a public native completion. During the durable `verifying` phase only, the phone can enter its saved key again and resume private verification polling with frame/input/start disabled. Reauthentication replaces the prior same-scope proof synchronously and preserves the original deadline; two pre-minted phone proofs cannot remain valid together. General active-view or verified-view reattachment is unavailable.

This is bounded reconnection, not automatic offline task continuation. The phone must return and submit the original protected controller interaction before its original deadline. SDK 0.6.132 supplies no durable native-call ID, reattachment or delivery acknowledgement; uncertain results are not resent. Lease rotation is at most five minutes per proof, with the original fifteen-minute ceiling and shorter job deadline. Reload/expired proof/worker replacement cannot adopt a retained browser.

The browser profile has an independent exact-ownership journal and a process writer record. Live cleanup confirms the exact process closed before recording/removing the same profile and releasing the journal. Ambiguous process/profile cleanup remains uncertain; restart recovery neither signals PIDs nor adopts browser state. Actual login and post-login restrictions still require live acceptance with the chosen iPhone and Oracle domain.
