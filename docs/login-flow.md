# Protected takeover and handback

The public SDK path connects synthetic control and separately gated experimental OCI CLI and Console jobs to their original native wait. The synthetic predicate never authenticates OCI. Real phone/control acceptance and actual OCI/cloud acceptance remain unverified. See [the OCI host flow](oci-host-flow.md) for its separate gates, runtime pins and verifier chain.

## Flow

1. A gated native `remote_login_request({mode:"synthetic",wait:true})` resolves the injected thread's actual environment and host, observes that host's configured control root, creates or joins a durable attempt, and opens the `login-control` interaction. Its public payload contains only `attemptId`.
2. The phone controller reads the attempt and shows its fixed host/context. It submits the separately provisioned phone key over the private HTTP channel to obtain an in-memory capability for that attempt's host-derived scope. It clears the raw key input after submission. Generic RPC identity and public interaction submission do not authorize control.
3. Private `/login/start`, `/frame` and `/input` calls derive the host, scope and principal from the stored attempt. They check the live SDK binding, host root, attempt revision and control proof before and after host operations. No caller can select another host, URL, context, script, selector or verifier.
   Every input also carries a required outer canonical UUIDv4 generated once by the client before serialization. It is separate from the event and grants no authority. After current authorization and operation barriers, the host spends the identity immediately before browser input; a transparent HTTP retry cannot apply that operation again.
   `/login/renew` replaces the control proof in the same viewer operation slot. Successful rotation keeps the browser, draft and focus intact. Host issuance and renewal enforce the attempt deadline in addition to the original fifteen-minute control ceiling; neither the phone nor a renewal can extend it.
4. For a synthetic attempt, the handback button shares the viewer's input/poll operation slot. The server records `verifying`, excludes input/frame operations and runs the host's fixed synthetic predicate. An empty/uncommitted test result returns to `user_control` without verification. A matching true result must be followed by confirmed browser closure and fresh binding/root/proof checks before `verified` is persisted. The host-only completion also creates the private, root-generation/browser-pin-bound 24-hour control receipt required by OCI; the form itself cannot issue that receipt.
5. The UI submits only `{attemptId}` to wake the original native call. The call independently checks durable synthetic verification, its original attempt identity, current host/root, revision and deadline. It calls `prepareResume()` before returning the bounded result. That records `uncertain`, never `delivered`.

An explicit native-card stop first waits for protected browser closure, then cancels the SDK interaction. Before OCI startup, the gateway revokes the private capability rather than requiring an existing target/browser lease. A failed close offers cancellation with cleanup explicitly unconfirmed. Leaving a view performs best-effort private closure without inventing a submission or cancelling another view's interaction. A test completed from history requires returning to the original waiting card; its read-only status check can offer public completion without reopening the browser.

The existing `/control/*` and `/fixture/*` diagnostic paths reject every stored job scope. A job capability cannot use those paths to bypass the coordinator during verification or after cancellation. The private gateway uses one operation per attempt and an eight-second combined request/disposal deadline; late data cannot reopen or advance a changed attempt.

The native form and final observations share the attempt's remaining durable lifetime. Rejoining an older attempt does not reset its deadline. SDK and host observations also have local cancellation races and eight-second bounds, so a transport that ignores abort cannot hold the original call indefinitely. Expiry remains distinct from explicit cancellation.

## Persistence and privacy

Only strict non-secret attempt state is persisted. The synthetic verifier returns a boolean; the OCI verifier returns fixed match facts and internal opaque receipt references. Neither exports input, DOM, claims or account identifiers. Frames, draft text, raw pairing key and capability stay out of the interaction payload, result, logs, ordinary RPC and durable state. Frames and input use the private capability channel. Cancellation records a cleanup command atomically; confirmed current-worker closure can acknowledge it. Failed or unknown cleanup remains pending.

These interfaces protect supported plugin operations. Arbitrary processes with the same OS user, BB administrators and other fully trusted plugins are outside that isolation boundary. There is no agent browser mode, cookie export, arbitrary CDP or shared personal profile in this stage.

Renewal consumes its old proof once. After the server attempts rotation, any timeout, cancellation or failed post-check terminates that matching attempt and retains owned cleanup; the server does not retry the consumed proof. The phone also terminates its controller after an uncertain rotation. A received late replacement can be used only for best-effort closure of its original attempt. A successful renewal never restarts or closes the browser. Before rotation, an authorization refusal does not change the legitimate job.

## Input acknowledgement uncertainty

Actual local Chrome replayed a POST after its first response socket was dropped: one app fetch produced two HTTP requests. Before the input guard, the joined Console browser applied the text twice. The fixed [input protocol](input-replay.md) keeps a private set of at most 4096 spent opaque identities per owned run, without event contents, eviction or cached success. Renewal and Console rejoin retain the set; same-scope closed-run tombstones prevent resetting it. A failed or uncertain browser call never releases its claim.

A repeated or exhausted identity is refused through conservative run cleanup. The viewer clears its frame, stops control and says that input may have executed and must not be directly resent. It does not infer delivery from an absent ACK, retry input automatically or submit native completion. Missing or malformed legacy identities fail with HTTP 400; app, server and host builds must support the matching contract.

## Remaining limits

- Each control grant lasts at most five minutes. A live viewer supports explicit manual renewal, bounded by its original fifteen-minute ceiling and job deadline. Expired, stopped or reloaded viewers cannot reattach; they require a new attempt. A private session is normally minted before that attempt starts. Console permits verification-only key rejoin after handback, with browser input still blocked. OCI acceptance uses a separate 24-hour control-path receipt; that receipt cannot extend an attempt or capability deadline.
- A public interaction submitted before verification cannot succeed. It ends that native wait with a fixed error; the safe attempt can still be inspected or cancelled. A later verification does not recreate the lost original call.
- SDK 0.6.132 has no durable native call ID, reattachment API or consumption acknowledgement for the eventual system message. The plugin does not resend through `threads.send`, and a possible delivery remains uncertain. Source and compiled harness results do not establish production delivery.
- A reload fails unfinished resource phases rather than reattaching to them. Persistent orphan-resource reconciliation is unfinished; unknown profiles are not deleted.
- OCI CLI uses its own owned child, restricted browser, guarded official diagnostic and independent sealed-snapshot SDK verifier. It can start only after the private control gate and expected target are accepted. CLI startup returns HTTP 202 and polls protected readiness before requesting frames. Handback can remain HTTP 202 while input/frame polling pauses and protected handback polling continues; manual proof renewal and stop remain available. Console uses its own gated [owned browser, independent identity verifier and retained-context reads](console-protocol.md). A phone callback bridge remains unavailable.
- CLI frame capture pre-arms one 1s DOM-content-loaded barrier before continuing an allowed GET main-frame document request to its fixed port-8181 callback. It awaits the same private marker, rechecks ownership/callback identity and consumes it before first capture; supersession/close cancels the marker and replacement refuses without resetting the wait. Puppeteer 25.16.0's `@internal` `ignoreSameDocumentNavigation` is an explicit narrow vendor-option dependency, probed with separate real steady-document hash tests before callback input. The corrected [controlled chain](../tests/oci-provider-navigation.test.ts) changes real inactive-page 403 to 200 with one capture after commit; [unit tests](../tests/oci-provider-browser.test.ts) cover refusal boundaries. The existing exact `Unable to capture screenshot` read retry remains separate. No inactive-error/input retry, PNG fallback, browser-policy or operation-deadline expansion is added; see [mobile evidence](mobile-browser-acceptance.md).
- This mobile/replay work has not reloaded the installed plugin. No real owner fingerprint/key, phone control acceptance, OCI authentication or cloud validation has been used. A general `accountRef` consumer and durable orphan/session recovery remain incomplete.
- Earlier targeted Chrome evidence covers 390×844 pairing timeouts, Console Chinese draft/focus/rotation/rejoin/ACK-loss and CLI callback/native/read. Later ordinary CLI failures despite screenshot retry/rendering wait remain history. The document-barrier controlled green and current post-barrier ordinary frontend 8/8 are separate targeted results. Historical normal failure was not reproduced; its exact category/same causality remains unproven. Full-source/compiled release verdicts are recorded externally. It does not establish universal navigation stability or complete RLOGIN-15. Source app/public SDK harness results do not establish installed BB-shell behavior, valid cloud credentials, physical-phone or native-consumption acceptance.

Private HTTP fetch and bounded response-body readers now settle on caller cancellation even if the transport ignores it; visible controller operations use the same deadline race. Strict raw renewal/handback responses remain separately observed for cleanup ownership, and cannot complete an aborted native card. A permanently missing Console acknowledgement remains ambiguous and relies on host expiry/durable cleanup rather than an unsafe browser-close assumption. Pairing diagnostics use the same bounded response handling. See the [fault evidence matrix](fault-matrix.md) for lower-layer, joined local-browser and remaining live acceptance boundaries.
