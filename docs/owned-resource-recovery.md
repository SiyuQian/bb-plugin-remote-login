# Owned OCI resources and conservative restart recovery

The production OCI session now has a private durable ownership journal. This supports cleanup after a worker exits; it does not restore an authenticated session, an `accountRef`, browser controls, a pending native call or a verified result.

Before creating its session root, the worker writes a scoped intent under `owned-resources-v1` in the existing private plugin data directory. Every exclusively created directory and file is recorded with its relative path, device, inode, owner, mode and creation time. Config, empty RC, private key, public key and token files are all precreated with mode `0600` before authentication. The pinned original OCI persistence functions overwrite those same inodes. Unknown files, replaced entries, symlinks, hardlinks and unsafe storage are refused.

The journal contains the full non-secret control scope and operating-system ownership facts. It contains no expected account identifiers, file contents, tokens, keys, URLs, cookies, screenshots or command lines. Session/resource handles remain opaque and cannot be reconstructed from this metadata. Journal files and lock files use mode `0600`, their directory uses `0700`, and changes use file and directory fsync around atomic replacement. Cleanup records each removal intent before unlink/rmdir, so an interrupted removal can resume without treating an unrelated missing entry as confirmation.

Before spawning authentication, diagnostic, verifier or read-only task children, the worker durably records a pending writer. It observes the exact `ChildProcess` immediately after spawn and records its PID, UID, process start identity and a digest of its executable path before sending private configuration. macOS observations use `libproc` start seconds/microseconds; the Linux observation includes process start ticks and boot identity. No process arguments or account files are inspected. The current macOS observer invokes the exact installed OCI CLI 3.88.0 Python path for its isolated standard-library/libproc helper; Console reuses this observer and therefore still needs that interpreter installation even though its identity and browser credentials are independent. Missing or unobservable process metadata is refused. Retention and successful completion wait for both exact process closure and durable writer closure. Closed non-browser history is pruned when a new writer starts, so normal read-only requests do not exhaust a retained session.

A missing exact close or an unsettled journal close returns `cleanup_uncertain` after the bounded cleanup budget. Cancelled writer preparation also returns uncertainty without spawning a child; its retainer is released only after the exact late intent is confirmed abandoned. Unknown ownership remains retained, and a late closure cannot turn that failure into verification.

The provider browser additionally records a pending browser writer before creating its fresh profile or launching Chrome. Its profile basename and exact root identity are private journal metadata. A browser writer becomes closed only after the owned process closes and that same profile is confirmed removed. A failed launch without a process handle remains pending. Optional requests to unsupported third-party assets are blocked; unsupported navigation still closes the browser. This does not add CDN or federated identity-provider support.

Restart reconciliation uses only an exact full-scope journal. It never signals a PID, including a matching or reused PID. A live, reused or unobservable old owner/writer remains uncertain. An interrupted spawn or unrecorded creation remains uncertain. A non-closed browser writer remains uncertain even after its PID disappears, because process absence cannot prove that its profile was removed. Unknown browser contents are not adopted or recursively deleted after restart.

When the old owner and all non-browser writers are demonstrably absent, browser closure is already durable, and every recorded filesystem identity still matches with no unknown entries, reconciliation removes only those recorded entries and retains a released tombstone. A retry can confirm that tombstone without adopting an unknown resource. A replacement worker cannot acknowledge a scope with no journal. Failure stays pending for operator recovery; default account directories and personal browser profiles are never consulted or removed.

Tests cover a real exited worker's empty precreated OCI session, actual pinned OCI persistence preserving file identities, interruption after unlink, unknown/replaced artifacts, PID reuse and visibility refusal, pending writers, browser cleanup uncertainty, and bounded private process/service fixtures. No real phone control, OCI authentication, cloud acceptance or installed-plugin reload was performed. Hostile same-user processes and privileged filesystem administration remain outside the isolation claim.
