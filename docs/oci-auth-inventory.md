# OCI adapter inventory — method boundaries

The enrolled Mac's shell exposes `/opt/homebrew/bin/oci`, version **3.88.0**. Version/help and fixed public installed sources were inspected; a reviewed read-only source compatibility helper now recognizes the launcher, Oracle session/bootstrap modules and Python browser module. No authentication, validation or cloud API was run, and no credential/config values were requested or returned. This is not daemon-worker compatibility or account-login evidence. See [the measured compatibility report and explicit disabled callback decision](oci-compatibility.md).

## Cross-device capability

OCI CLI documents session export from a machine with a CLI and browser, followed by import on the target. An iPhone without OCI CLI is not that documented source. `--no-browser` relies on existing API-key or session authentication; it is not an initial device-code flow. The authenticate command has no documented redirect-URI, callback-port or device-login option. [Token authentication and transfer](https://docs.oracle.com/en-us/iaas/Content/API/SDKDocs/clitoken.htm), [authenticate options](https://docs.oracle.com/en-us/iaas/tools/oci-cli/latest/oci_cli_docs/cmdref/session/authenticate.html)

IAM Identity Domains separately supports a device-code grant for configured client applications. Its existence does not establish support in OCI CLI or turn its OAuth access token into a CLI security token. Register those capabilities separately. [Identity Domains device grant](https://docs.oracle.com/en-us/iaas/Content/Identity/api-getstarted/DCGT.htm)

## Host browser and optional callback adapter

The pinned 3.88.0 browser implementation creates an ephemeral key and nonce, opens an Oracle authorization endpoint, and redirects to `http://localhost:8181`. The upstream listener binds all interfaces; page JavaScript forwards the response fragment to its token receiver. A phone's localhost is the phone, so opening this URL there does not complete the host's callback. [Pinned Oracle bootstrap source](https://github.com/oracle/oci-cli/blob/v3.88.0/src/oci_cli/cli_setup_bootstrap.py)

The primary design keeps that browser and callback on the selected host and relays only the protected picture/input channel. Do not expose the callback listener through BB Connect. Check port ownership and lifecycle before starting a job; never kill or adopt an unrelated listener. Installed source hashes now match the pinned upstream modules. The original unguarded CLI path is unsuitable: Python's `BROWSER` hook can fall back to a system browser, and the receiver has no attempt/nonce checks. The separate registered host adapter applies its reviewed wrapper and ownership checks; phone callback forwarding remains unavailable. The new fixed helper reads source only; it does not test a live CLI listener or account flow.

## Independent verification

Normal `oci session validate` performs an online Identity regions request. `--local` checks expiry only. Future authorized verification must discard stdout/stderr and retain exit status; a successful CLI process or token-shaped string is insufficient. Session persistence may omit `user`, so that config field is not authoritative identity. After online acceptance, compare the validated session's tenancy and subject privately against preselected expectations. [Validation reference](https://docs.oracle.com/en-us/iaas/tools/oci-cli/latest/oci_cli_docs/cmdref/session/validate.html), [pinned session implementation](https://github.com/oracle/oci-cli/blob/v3.88.0/src/oci_cli/cli_session.py)

Console verification is separate. Oracle documents user profile and tenancy details, including the relevant identifiers. A limited in-worker verifier should match the expected user/tenancy and domain or realm and return only allowlisted match results. A Console URL, display name, user acknowledgement or successful CLI session does not verify the browser context's identity. Do not export cookies or raw DOM. [Profile details](https://docs.oracle.com/en-us/iaas/Content/Identity/usersettings/get-details-my-profile.htm), [tenancy identifiers](https://docs.oracle.com/en-us/iaas/Content/GSG/Tasks/contactingsupport_topic-Locating_Oracle_Cloud_Infrastructure_IDs.htm), [user identifiers](https://docs.oracle.com/en-us/iaas/Content/Identity/Tasks/managingusers.htm)

Registered host-browser adapters remain gated and not live-accepted. Required next evidence includes owner-provisioned iPhone pairing, the protected synthetic control path, fail-closed browser capture, correct callback ownership and containment, expected-account checks and both real OCI flows. The installed-source compatibility gate has read-only evidence; it does not authorize either flow. The [method registry](provider-capabilities.md) separately checks queue eligibility without authenticating. No account has been authenticated by this inventory.
